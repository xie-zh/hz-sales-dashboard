# SalesPulse · 销售运营数据中台

> 把散落在 Excel 里的业务数据，变成每天自动上线的决策看板。
> **在线演示**：打开仓库首页（或 Pages 地址）→ 点击任意看板卡片，全部功能可交互。

一套面向销售团队的数据运营系统。从企业 BI 取数、Excel 公式重算、指标口径计算，到静态看板生成、指纹判变发布、企业微信群推送——全链路无人值守。

覆盖三条业务线：**活动量考核**、**组织健康度诊断**、**通话质检评分**。累计支撑百人级团队日常经营，日更 9 个在线页面。

---

## 一、这套系统解决什么问题

销售团队的考核数据原本散落在多个 Excel 表里：每天人工汇总、算达标率、做报表、发群。

问题很具体：

- **慢** —— 一份全量报表手工整理要 40 分钟以上
- **易错** —— 跨表公式引用错一处，整张表的口径就歪了
- **口径不一** —— 不同人算同一个「达标率」能算出三个数
- **看不到趋势** —— Excel 里没有历史留存，无法对比上周、上月

系统把这条链路整个自动化：

```
企业 BI 报表 ──► Excel 源表 ──► 解析计算 ──► 静态看板 ──► 云端发布 ──► 群内推送
   (每日自动)     (COM 重算)      (Python)     (9 个页面)   (指纹判变)    (图片+文案)
```

## 二、在线演示

打开仓库首页，9 个看板全部可点击。**功能完全真实可用**：筛选、排序、搜索、图表联动、Tab 切换、历史趋势查询都能操作。

| 看板 | 内容 |
|---|---|
| **活动量看板** | 核心看板。KPI 总览、部门过程量、全员明细（总表 / 法律日达标 / 会计达标 / 资质达标）、图表分析、历史趋势 |
| **员工三力** | 人力结构四层分级：英雄人力 / 标准人力 / 破零人力 / 无效人力 |
| **经营健康度** | 四大经营模式统一打分，含指标口径规则库、复合健康分、多级下钻 |
| **通话质检评分** | 827 条录音增量转写，五维自动评分并给出改进建议 |
| **网销数据分析** | 网销漏斗逐人逐环节拆解，定位转化断点 |
| **电邀数据分析** | 电话邀约过程量追踪，通时 / 拨打 / 接通三率联动 |
| **会计数据分析** | 财务侧活动量考核，含票据抽检与个人出错率 |
| **业绩含续费** | 新签与续费合并口径，事业部 / 团队 / 个人三级下钻 |
| **订单商品明细** | 订单级明细穿透查询，多条件组合筛选 |

### 核心能力

- **多维度筛选** —— 事业部 / 部门 / 姓名工号搜索，实时联动全部图表与表格
- **双口径考核** —— 「当日达标」与「滚动周考核」独立呈现，分母口径严格区分
- **历史趋势** —— 按日 / 按月聚合，支持多日期叠加对比
- **指纹判变** —— SHA256 内容指纹比对，无变化则跳过构建与发布
- **零依赖部署** —— 纯静态 HTML + JSON，任意静态托管即可运行
- **数据兜底** —— 页面内嵌数据，`fetch` 失败自动降级，永不白屏

## 三、三个子系统

仓库包含三套可独立运行的系统，共用同一套数据口径与部署约定。

### 1. SalesPulse Dashboard —— 数据看板主体

`src/` + `demo/`。四阶段流水线，9 个页面，单文件 HTML 可离线分发。

### 2. ReportFlow —— BI 报表自动化流水线

`modules/reportflow/`。BI 系统登录取数 → 跨表 Sheet 复制 → HTML 导出与后处理 → Web 目录发布。

含可视化配置编辑器（Tkinter）、任务调度器、COM 引擎进程管理、磁盘清理策略。
把「每天手工下载 10 张报表再复制粘贴」压缩成一次双击。

### 3. BriefKit —— 企微数据战报机器人

`modules/briefkit/`。把看板数据渲染成图片 + 文案，定点推送到企业微信群。

三条独立链路（活动量 / 三力 / PK），支持测试群灰度、发送结果校验、失败只报错不重试。

## 四、技术架构

### 4.1 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 数据处理 | Python 3.11 / openpyxl | Excel 解析生态最成熟 |
| Excel 写入 | WPS / Excel COM 自动化 | 需保留公式重算能力（openpyxl 会丢公式缓存） |
| 前端 | 原生 HTML/CSS/JS + ECharts 5 | 无构建步骤，单文件可分发 |
| 调度 | Windows 计划任务 | 免安装、免常驻、崩溃不影响下次 |
| 部署 | 静态托管 + 对象存储 | 成本低、覆盖式发布保持链接稳定 |
| 语音转写 | 腾讯云 ASR | 长音频、中文识别准确率满足要求 |

**为什么不用 React / Vue**：数据量小（百人级）、页面数量少（9 个），且核心诉求是「单文件可独立运行、可离线归档、可任意转发」，引入构建链反而增加部署复杂度。

### 4.2 数据流水线

单次执行四个阶段：

```
阶段1  BI 取数     并发下载 12 张报表 → 写入 Excel 源表
阶段2  Excel 写入  WPS COM 整块写入（保留公式并触发重算）
阶段3  构建        解析 → 计算考核 → 生成 9 个页面 + JSON 数据层
阶段4  发布        指纹比对 → 有变化才发布 → 线上核验
```

**关键设计：指纹驱动的零成本判变**

```
build_hash = SHA256(所有产物的规范化内容)
上次发布指纹存于 _published.json
两者一致 ⇒ 直接跳过，省去构建与发布
```

配合退出码语义（`23 = DEPLOY` / `0 = SKIP`），调度器无需解析日志即可决策。

单次全量执行约 100 秒；无变化时约 20 秒判定跳过。

## 五、踩过的坑

这部分比代码更能体现真实工程能力。

### 5.1 Excel 公式必须靠 COM 重算

源表含 **2.8 万个公式**与 9 张透视表，其中约 700 个 XLOOKUP 跨表引用。
用 openpyxl 读写会**丢失公式缓存值**，导致看板读到 `None`。

**解决**：写入必须走 WPS COM 自动化，写完等文件句柄释放再构建。

### 5.2 高完整性进程读不到用户级 COM 注册

Windows 计划任务以高完整性（High IL）运行时**不读取 HKCU 用户级注册表**，而 WPS 只把 Excel COM 类注册在 HKCU ⇒ 计划任务里调用必定失败，手动双击却正常。

**解决**：启动时自愈——把 ProgID / CLSID / LocalServer32 补写进 HKLM。

> 试过降权重启、`CreateProcessAsUser`、经 explorer 启动三条路，**全部无效**，
> 注册表自愈是唯一可行解。

### 5.3 员工不在主表里

主表 sheet 只含 4 个事业部 22 人，**会计 16 人不在其中**。
最初以为看板 bug，实际是数据源结构如此。

**解决**：为会计单独挂载数据通道，前端按数据存在性自动显隐。

### 5.4 双口径不可混算

「当日是否达标」与「滚动周活动量合格」是两套独立考核口径。
周合格率分母**只能算正常考核人员**（会计 16 人中 5 人不考核活动量），算错会让合格率虚高 40%。

### 5.5 敏感字段只能置空，不能删除

脱敏脚本最初直接 `pop` 掉音频地址与转写字段，结果前端读 `undefined` 抛错，**整页渲染中断**。

**解决**：保持数据结构契约稳定——字段保留、值置空。这条规则后来写进了代码规范。

### 5.6 发布链接跟账号走

静态托管的分享链接绑定发布账号，换账号必须重新发布。
**旧链接一旦公开就无法完全回收**——这是做公开演示必须先全量脱敏的原因。

## 六、安全与脱敏

本仓库是**脱敏演示版**。真实生产数据含员工姓名、工号、客户信息、通话内容，公开前由脱敏脚本统一处理：

| 项目 | 处理方式 |
|---|---|
| 员工姓名 | 确定性哈希映射为虚构姓名（同一人始终同一化名），共 174 个身份 |
| 工号 | 重新编号为 `100000+` 区段 |
| 组织名 | 改为通用名称，剥离城市与公司标识 |
| 客户信息 | 客户公司全称替换为「示例客户 NNN 公司」 |
| 合同号 / 订单号 | 替换为 `<SERIAL_NO>` 占位符 |
| 通话数据 | **音频地址、转写正文、分段文本全部清空**，仅保留评分维度 |
| 密钥 / 账号 / 内网地址 / 本机路径 | 完全剔除 |
| 历史留档 | 裁剪至最近 7 天，逐日同样脱敏 |

脱敏采用**结构化字段处理 + 全文本全局替换**双层机制：先按字段名对 JSON 做结构化映射，
再对所有文本（含 HTML 注释、内嵌兜底数据块、深层嵌套数组）做姓名全集替换，避免只处理表层而漏掉嵌套结构。

脱敏脚本与校验脚本一并入库（`src/ops/`、`tools/`），可复现、可审计。

## 八、如何运行

### 演示站

打开仓库首页或 Pages 地址，**无需任何环境**，所有交互功能均可点击。

### 本地运行

```bash
pip install openpyxl

# 本地预览
cd demo && python -m http.server 8000
# 打开 http://localhost:8000/index.html
```

### 生产环境初始化

```bash
python src/ops/portable_setup.py scan      # 环境体检（13 项）
python src/ops/portable_setup.py fix       # 一键修复：建 venv + 装依赖 + 写配置
python src/ops/setup_new_machine.py --yes  # 新机器 9 步初始化
```

## 九、可迁移性

系统在设计之初就考虑了跨机器、跨账号迁移：

- **路径零写死** —— 所有路径走统一 resolver，靠标记文件自动定位项目根
- **配置集中** —— 单一配置文件描述发布通道、链接、账号、路径
- **自包含** —— 离线依赖包随包携带，断网也能建环境
- **一键打包** —— 生成搬家包，新机器双击 bat 完成部署
