01 / 系统架构

四阶段数据流水线 单次全量执行约 100 秒；无数据变化时约 20 秒判定跳过，不产生任何构建与发布开销。

WPS COM 整块写入，触发 2.8 万个公式重算，保留透视表缓存
~14s

STAGE 03
解析与构建
多 Sheet 协同解析 → 口径计算 → 生成 7 个页面 + JSON 数据层
~57s

STAGE 04
判变与发布
SHA256 内容指纹比对，有变化才上传，发布后自动线上核验
~7s
核心设计：指纹驱动的零成本判变。 所有产物规范化后计算 SHA256，与上次发布指纹比对，一致则整段跳过。 配合退出码语义（23 = DEPLOY / 0 = SKIP），调度器无需解析日志即可决策， 避免重复上传与无谓算力消耗。

03 / 工程难点

真实踩过的坑，比代码更能说明问题 以下每一条都在生产环境真实发生过，解决方案经过验证。

问题现象根因与解决
看板读到的指标全是 None 源表含 2.8 万个公式与 9 张透视表，其中约 700 个 XLOOKUP 跨表引用。openpyxl 读写会丢失公式缓存值。改为 WPS COM 整块写入并等待句柄释放，公式实时重算。
手动运行正常，计划任务必定失败 Windows 计划任务以高完整性（High IL）运行时不读取 HKCU 用户级注册表，而 WPS 只把 Excel COM 类注册在 HKCU。试过降权重启、CreateProcessAsUser、经 explorer 启动三条路均无效；最终方案是启动时自愈——把 ProgID / CLSID / LocalServer32 补写进 HKLM。
某事业部员工在看板上「消失」 主表 sheet 只含 4 个事业部 22 人，会计 16 人不在其中——不是 bug，是数据源结构如此。为该板块单独挂载数据通道，前端按数据存在性自动显隐。
周合格率虚高 40% 「当日是否达标」与「滚动周活动量合格」是两套独立口径。周合格率分母只能算正常考核人员（会计 16 人中 5 人不考核活动量）。前端显式标注口径，双口径绝不混算。
页面加载后偶发整页空白 数据层字段被裁剪后，前端读 undefined 抛错中断渲染。确立规则：敏感字段置空而非删除，保持数据结构契约稳定；同时页面内嵌兜底数据，fetch 失败自动降级，永不白屏。
发布链接换账号即失效 静态托管的分享链接绑定发布账号。旧链接一旦公开无法完全回收——这是所有公开演示必须先做全量脱敏的根本原因。

05 / 技术栈

选型原则：够用、可迁移、零运行时依赖

Python 3.11 openpyxl WPS / Excel COM 自动化 ECharts 5 原生 HTML/CSS/JS Windows 计划任务 SHA256 指纹判变 静态托管 / 对象存储 Selenium 腾讯云 ASR LLM 结构化评分 企业微信 Webhook

为什么不引入 React / Vue

  • 数据规模小（百人级）、页面数量少（9 个），引入构建链反而增加部署复杂度
  • 核心诉求是「单文件可独立运行、可离线归档、可任意转发」——纯静态 HTML 天然满足
  • 页面内嵌数据兜底 + JSON 外挂，fetch 失败自动降级，弱网与断网都能打开
06 / 数据脱敏

公开演示版做了什么处理

对象处理方式
员工姓名确定性哈希映射为虚构姓名（同一人始终对应同一化名），共处理 174 个身份
工号重新编号为 100000+ 区段，保证不与原号冲突
组织架构事业部 / 部门名改为通用名称，剥离城市与公司标识
客户信息客户公司全称替换为「示例客户 NNN 公司」，合同号 / 订单号替换为占位符
通话数据音频地址、转写正文、分段文本全部清空，仅保留评分维度与结论
基础资源密钥、账号、内网域名、本机绝对路径、对象存储桶名全部剔除
历史留档裁剪至最近 7 天，逐日同样脱敏

脱敏采用结构化字段处理 + 全文本全局替换双层机制：先按字段名对 JSON 做结构化映射， 再对所有文本（含 HTML 注释、内嵌兜底数据块、深层嵌套数组）做姓名全集替换， 避免只处理表层而漏掉嵌套结构。脱敏脚本与校验脚本一并入库，可复现。
