# 规则：业务口径与发送规范

## 一、企业微信发送规范

### @ 提及（血泪教训，勿回退）

- aibot 的 markdown **只有 `content` 字段，没有 `mentioned_list`**；`message send` 也只支持纯文本。
  → **无法真正 @ 任何人**。
- 正文写 `<@userid>` **不会被渲染**，而是原样显示成 `<@woPClcBwAA…>` 乱码（2026-10-09 真实事故）。
- `wecom-cli contact users search` 返回的 `userid` 是**框架加密句柄**（连授权真人也是此形态），不是企微真实 userid。
- ✅ 做法：文案里写**纯文本 `@姓名`**；如需真提醒，只能改用**群机器人 Webhook**
  （`text` + `mentioned_list`，需**真实 userid 或手机号**），地址填 `_common/webhooks.json`。

### 其它

- 发送失败 **只报告 errcode/errmsg，不重试**（`errcode 850003` = 授权过期 → 提示重新扫码授权）。
- 每次发送后用 `show_result.py` / `show_hero_result.py` 汇总，确认 `ALL_SUCCESS`。
- 群发前先试发测试群：`REPORT_GROUP="3C认证"`。
- 文案时间取**发送当刻**，不要写死。
- 图片 `media_id` 必须用 `type=image` 上传，且 `chat_id` 必须取自**本次** `sessions list`。

## 二、活动量口径

- 数据源：看板 `data.json`（`total` = 业务部门；`legal` = 法律事业部，两块人员不重叠，合计才是全员）。
- 未达标：`是否达标 == "不达标"`；`"免考核"` 追踪模式不列入、结果模式展示灰色徽章。
- 「分钟」：活动量单位即分钟，`目标`（≈`折扣目标`）= 60；**距达标分钟 = 折扣目标 − 完成**（四舍五入、下限 0）。
- **法律板块没有分钟概念**（`目标`/`折扣目标` 为空、`今日完成` 是 0/1「日达标」标记）→ 文案中法律单独一行列出，不给分钟。
- 文案格式（定稿）：
  ```
  今日H点M分活动量{追踪|结果}数据：<链接> ({说明}
  未达标 N 人（业务 a · 法律 b）· 距达标还剩：
  @姓名 还差 X 分钟 ｜ …（业务逐人）
  法律日达标未达成 b 人：@姓名 ｜ …      （仅追踪模式、且法律有未达标时）
  ```
- 链接规则：**无结尾斜杠、链接后留一个空格、无结尾右括号**。

## 三、三力口径

- 源：`企服顾问明细` sheet（第 3 行表头、第 4 行起数据）；周期由文件名日期戳推导（日 ≥ 15 → 下月周期）。
- 达成口径统一：当月签单实算业绩 Q > 0 且 0 < 差距 < 3000；列位随周期位移，**改版先核对列位**。
- 事业部汇总**直读官方「事业部汇总」sheet**（按表头名定位列，防位移）；官方口径：
  **英雄/标准/破零 率 ÷ 月初人数，有效占比 ÷ 考核人数**（考核人数 = 明细 AZ 列「是否考核有效人力=是」）。
- 官方「标准人力」= 明细 W 列，**不等于**正文用的「英雄 50%」（AG 列）——两个不同指标，勿混。
- 发送顺序固定 **11 条**：汇总文案 + 汇总图在最前，特权海报永远最后。

## 四、PK 口径

- 流程：静默同步业绩（`sync_yj.one_cycle(notify=False)`）→ 变化检测 → 截图（含两张活动海报）→ 文案 → 发送。
- 跨目录依赖：`业绩BI同步/sync_yj.py`、`scratch/capture_pk2.py`、`src/core.py`（登录态/Edge 探测）。

## 五、工程约定

- 改脚本走：项目 `源码/` 编辑 → `python tools/sync_to_runtime.py --dry` 看差异 → 推送 → **实测**。
- 定时任务调用的是**运行目录**里的固定路径，不要擅自改路径。
- Python 调 `wecom-cli` 必须 **node 直调 `wecom.js`**（`wecom-cli.CMD` 无法被 `CreateProcess` 执行，会静默失败）。
- 疑似代码异常时**以原始字节为准**（`open(path,'rb')`），工具输出偶有显示错乱。
- **换行符必须 LF**：`.sh` 含 CRLF 会直接执行失败（`invalid option` / `$'\r': command not found`）。
  仓库已用 `.gitattributes` 锁定 `eol=lf`；同步工具遇到含 CRLF 的 shell 脚本会**中止同步**并告警。
- **云端沙箱（`/workspace`）不能跑战报**：缺 Python/node 环境与企业微信授权，且脚本内部是 Windows 绝对路径。
  云端只做协作（改源码、审口径、写文档）；真要发送必须回到本机数据节点执行。
