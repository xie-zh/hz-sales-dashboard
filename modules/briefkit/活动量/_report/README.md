## 达标口径

| 岗位 | 达标判定 |
|---|---|
| 网销岗 | **24:00 达标率 ≥ 100%**（源站口径） |
| 电邀岗（=电销） | **6 项中「任意一项」达标即算达标**（用户口径，2026-10-10 确定）——加微 / 精准审核 / 业绩 / 见客 / 意向 / 45s，各 0/1 标记，求和 ≥1 即达标 |
| 综法岗 | **19:30 达标率 ≥ 100%**（源站口径） |

考核为 0 视为**未考核**，不计入未达标名单。

> ⚠️ 电邀岗的达标判定与**网页默认口径不同**：网页/页面引擎 `RBE` 的第 2 个基准是
> 「**6 项全中**」（`N6` 常量：加微≥5 / 精准审核≥1 / 业绩≥1000 / 见客≥1 / 意向≥3 / 45s≥20，
> 2026-10-08 起第 6 项由「接触数≥135」改为「45s≥20」）。
> 我们按用户要求改成「任一项 ≥1」，所以：
> - `render_wb.py` 不再直接用引擎给的 `n6pass` / `n6rate`，而是用 `dx_any()` 按人员明细重算
>   （部门级与整体表同样重算）；
> - 图③（电邀）的脚注会显式写明这条口径，避免与网页对不上时被误判为脚本错误。
> - 实证（2026-10-09，电邀）：旧口径「6 项全中」达标 0 人；新口径「任一项」达标 1 人（徐伶 1/6）。

## 取数（`wb_source.py` + `wb_engine.js`）

### 1) 下载页面（2 步，**版本号每次重新发布会变，必须现取**）

```
1) GET https://dashboard.example.com/p/<nodeId>
     → 外壳页，含 window.__PUBLISH_BOOTSTRAP__ = {... "publishVersion": N ...}
2) GET https://workbuddy-space-static.codebuddy.work/page/<nodeId>/<N>/七岗排行榜.html   （约 16 MB）
     → 内嵌 var RB = {...} / var DASH = {...} / var RBE = (function(){...})()
```

- `RB.cycles[周期]` = **按人按天原料**：`days` 日轴（`{d:'YYYYMMDD', x:剔除日标记}`）、
  `posts[岗].ppl`（网销/电邀/大客户/会计：每人每天 30 列，列下标见 RBE 里的 `F_*` 常量）、
  `posts2[岗].ppl`（综法/中台）、`posts3[岗].ppl`（资源）。
- `DASH.cycles[周期].data[岗]` = **预构建的【全周期】结果**（含 `titles`/`keys`/`children`/`total`）。

### 2) 用页面自带引擎重算【日】档（**关键**）

页面数值不是静态的：不同日期档位由页面内嵌引擎 **`RBE`**
（工作台 Python 侧 `gen_rank_all/gen_rank5` 的 JS 复刻，随页面发布）按区间重算。
所以「日」档必须用同一套引擎，否则数值对不上页面。

`wb_source.fetch_day()` 的做法：
1. 把 `RB` / `DASH` 落盘为 `_cache/RB.json` `_cache/DASH.json`，把 `RBE` 源码原样抽到 `_cache/rbe.js`；
2. 取数据日：**`render_all()` 传当天 `day=YYYYMMDD`**，三岗统一；不传 `day` 时才会回退到
   `day_anchors()` 的「各岗各自锚点」旧行为（保留该函数，仅供手动排查用）；
3. 用受管 node 跑 `wb_engine.js`（`RBE.build` / 综法用 `RBE.build4`），拿到 `children['分公司']['']`
   与 `children['部门'][部门]`，整理成与 `fetch()` 完全相同的 `hz[岗] = {titles, keys, depts, people}` 结构。

**校验**（2026-10-09，v492）：引擎输出与页面截图逐格一致 ——
网销岗 在职 269 / 考核 146 / 24:00 达标率 58.2% / 冲刺率 1.6% / 日均通时 47.8 分。

### 坑

- 各岗位 `lead` 结构不同（电邀/网销/会计 = `[城市,业态,部门]`，中台 = `[业态]`，综法 = `[城市,部门,"-"]`），
  用 `wb_source._match_dept()` 配对：**先精确（lead 元素 == 部门键）、再包含（元素长度 ≥4）**。
  只用「包含」会让城市名「」命中**任意**部门，导致多个部门取到同一行。
- 页面每约 5 分钟刷新一次数据（`QGG_REFRESH`），`fetch_day` 默认缓存 10 分钟以内的页面；
  定时任务每次跑到的都是当次最新数据。
- 字段与实测数据见项目文档 `资料/新数据源与口径（活动量改版）.md`。

## @ 提及的真相（2026-10-09 实测，勿回退）

❌ **aibot 通道无法真正 @ 任何人**：markdown 只有 `content`、没有 `mentioned_list`；
正文写 `<@userid>` 不会被渲染，而是原样显示成乱码 `<@woPClcBwAA…>`；
`contact users search` 返回的 `userid` 是**框架加密句柄**（连授权真人也是此形态），写进正文不会被解密。

✅ 现有做法：`mention_util.mention()` 输出**纯文本 `@姓名`** —— 可读、无乱码，但**不触发提醒**。
🔧 要真提醒只能走**群机器人 Webhook**（`text` + `mentioned_list`，需真实 userid 或手机号），
地址填 `数据文件/_common/webhooks.json`（当前为空）。
