从「三力 & 有效人力」追踪表读取数据，生成 4 张汇报图 + 1 张**事业部汇总图** + 1 张特权海报，
推送到企业微信「**数据点检群**」（原 🤡集团3C认证团队🤡 **已停发**）。
**每次由人工触发**（把 xlsx 给我，或告我路径），发送前由群机器人 Webhook 真 @所有人，
**事业部汇总（文案+表图）永远在战报最前一条，特权海报永远保持在最后一条**。

## 一、日常使用（每次要发时，人工触发）

**方式 A（推荐）—— 把 xlsx 发我 / 告诉我文件路径，一条命令发送：**


（不带 `--force` 时只在出现**更新日期**的文件时才发，同日修正版不重复发；`--check` 只检测不发送。）

## 计算口径（2026-09-24 最终版）

### 统一筛选规则（**四个追踪共用**）

- **差距 = 目标值 − 当月签单实算利润业绩(R)**（不是减业绩 Q）
- **排除「当月签单实算业绩 Q（第 17 列）≤ 0」的人** —— 业绩为 0 或负数一律不进榜
- **且 `0 < 差距 < GAP_LIMIT`**（`GAP_LIMIT = 3000`，**严格小于**），按差距**升序**排列

### 各追踪用到的列

| 追踪 | 是否达成列 | 标准列 | 说明 |
|---|---|---|---|
| 英雄人力（全月） | Z(26) == "是" | Y(25) | 达成 → 本月全月活动量免考核 |
| 英雄人力（50%） | AG(33) == "是" | AF(32) | 达成 → 下半月免考核；**50% 恭喜名单要去掉已达成全月的人** |
| 破零人力 | T(20) == "是" | S(19) 门槛破零标准值 | 文案收尾「这几位伙伴即将达成破零，冲刺一把！」 |
| 有效人力 | AN(40) == "是" | AO(41) 实算利润业绩标准 | AN 另有「不考核」值，只有 `== "否"` 才参与差距榜 |

- 已达成者不进对应差距榜；`标准` 或 `利润` 为空者不参与
  （如 张志梅 / 梁丹宁 / 阮亚婷 / 汤跃斌 无破零标准值）
- ⛔ **已废弃口径**：① 曾用「距有效人力(AO) 与 距英雄人力(Y) **都** ≤5000 的交集」= 12 人（用户否定）；
  ② 曾用「利润 R > 0 且 ≤5000」、破零「≤1000」—— 2026-09-24 统一为上面的 **Q > 0 且 差距 < 3000**。

### @全体成员 的写法（重要）

企业微信**智能机器人(aibot) markdown 不可靠地触发 @全体**——`<@all>` 多数情况下只是字面显示、不真的提醒。
因此**真实 @全体改由「群机器人 Webhook」负责**：`run_hero.sh` 在发送前调用 `send_atall.py 数据点检群 "…（含各事业部汇总），请各位伙伴查看 👇"`。
（Webhook 未配置则 `|| true` 静默跳过，不阻塞主流程。）

`@单人` 由 `mention_util.py` 负责：通讯录授权后把姓名解析成 `<@userid>` 真@单人；未授权（`errcode 850002`）则自动
回退为纯文本 `@姓名`，并在 `wecom_users.json` 写 `_disabled=True` 之后不再联网。

## 踩坑记录
1. **群文件只能走企微本地缓存**：`chat groups list` / `chat messages list` 本企业禁用（errcode **853006**）。
   路径 `<DATA_CACHE>/<账号>/Cache/File/<年-月>/`；本次账号 `1688857640763810`。
2. **表头在第 3 行**（A1 标题、第 2 行分组名）；按第 1 行取表头会错位。
3. **不同周期文件的列位会整体位移**：9月周期版 `英雄标准/达成/差距 = X/Y/Z`、50% 档 `= AE/AF/AG`；
   10月周期版**右移一列**（多了「岗龄调整(月初)」）→ `Y/Z/AA`、`AF/AG/AH`。
   **换周期文件时必须先核对表头行**，不能沿用硬编码列号。
4. **定位"某条群文案出自哪版文件"**：拿文案里的几个特征值（如利润 1053 / 4675 / 22771.15）去各版本 xlsx
   逐行比对，命中数最高的那一版即是 —— 本次借此确认参考文案出自 `20260827` 版（7/7 命中）。
5. **微软雅黑 msyh.ttc 无 emoji 字形**：图内写 emoji 会渲染成方框 □ → 图内改用 `已达成` 文本徽章，emoji 只放文案。
6. **路径必须 Windows 风格**（`C:/...`）；`/c/...` 会被 Windows 程序解析成 `C:\c\...`。
7. 用 venv 的 `python.exe`（`.../envs/default/Scripts/python.exe`，含 Pillow / openpyxl）。
8. **周期日期自动推导**（`cycle_info()`）：取源文件名里的日期戳，
   **日 ≥ 15 → 属「下月」周期；日 ≤ 14 → 属「当月」周期**
   （例 `20260923` → 10月周期 9/15–10/14；`20260914` → 9月周期 8/15–9/14）。
   文件名没有日期戳（如 `src_latest.xlsx`）时回退读 `src_latest.meta.json` 记录的原始文件名
   —— 否则会拿"今天"当数据日，导致周期/免考核日期错一天。
9. **自动化幂等的关键**：`watch_state.json` 记 `last_ymd`，只有**严格大于**才发送。
   同日多版本（`(1)` / `(终版)` / 体积不同）**不重发**，避免同一天刷屏；确需重发用 `--force`。
10. **`subprocess` 调 `bash` 走同一套环境**（PATH 含 PortableGit，`wecom-cli` 可解析）；
    实测 `bash --version` / `command -v wecom-cli` / `media upload` 均 OK —— 自动化里可安全用 `subprocess.run(["bash", ...])`。
11. **@所有人 的正确写法**：机器人 markdown **不支持** `mentioned_list` 参数（传了无效、不提醒），
    必须在 **content 正文里**写 `<@all>`（= @所有人）/ `<@userid>`（= @某人）才会真正触发提醒。
    `[庆祝]` 这类短代码也不会转成表情 → 图内/文案里用真实 emoji（`🎉`）。
12. **目标群关键字**：`assemble_hero.py` 里 `GROUP_KEY = "数据点检群"`。
    ⚠️ `chat_id` **每次都要重新 `sessions list` 获取**（会变、且不同群前 8 位可能相同，别硬编码复用）。
13. **首次接入新群**：机器人需先被拉进群，`sessions list` 里才会出现该群；否则 `assemble` 直接报"未找到群"。
14. **口径统一（2026-09-24）**：四个追踪一律「**当月签单实算业绩 Q > 0** 且 **差距 < 3000**」。
    注意与旧口径「利润 R > 0」**不是一回事**：Q>0 但 R<0 的人（如 王玉 Q=1324.5 / R=−73）旧口径会被剔除、新口径才进榜。
    改口径时 `GAP_LIMIT` 与 `has_q()` 要一起改；`GAP_LIMIT` 用**严格小于**。
15. **有效人力列**：`AN(40) 是否达成有效人力` 有三种取值 —— `是` / `否` / **`不考核`**；差距榜只取 `== "否"`
    （"不考核"的人不该被催）。差距用 `AO(41) 实算利润业绩标准 − R`，与表内 `AP(42) 差距` 逐行一致（已校验）。
