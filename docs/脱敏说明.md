# 脱敏说明

公开仓库里的所有数据均为虚构。本文说明脱敏做了什么、怎么做的、如何校验。

---

## 一、处理对象与方式

| 对象 | 出现位置 | 处理方式 |
|---|---|---|
| 员工姓名 | JSON 人员数组、HTML 表格、图表图例、字典键 | 确定性哈希映射为虚构姓名（同一人恒对应同一化名） |
| 工号 | 人员记录 | 重新编号至 `100000+` 区段，避开原号段 |
| 事业部 / 部门 | 组织字段、跨表关联、颜色映射表 | 映射表 + 通用后缀剥离，去城市化 |
| 岗位名称 | 人员记录 | 替换为等价通用岗位名 |
| 客户公司全称 | 订单 / 漏斗 / 质检记录 | 替换为「示例客户 NNN 公司」 |
| 合同号 / 订单号 | 明细数据 | 替换为 `<SERIAL_NO>` |
| 通话音频地址 | 质检记录 `audioUrl` | **置空**（保留字段结构） |
| 通话转写正文 | `transcript` / `rawTranscript` / `segments` | **置空**，仅保留评分维度与结论 |
| 入职日期 | 人员记录 | 统一为 `20XX-01-01` |
| 历史留档 | `hist/` 每日快照 | 裁剪至最近 7 天，逐日同样脱敏 |
| 密钥 / Token | 配置文件 | 完全剔除，配置模板保留 `<WEBHOOK_KEY>` 占位 |
| 内网域名 | 代码、配置、页面文案 | 替换为 `*.example.com` |
| 本机绝对路径 | 脚本、配置 | 替换为 `<PROJECT_ROOT>` / `<HOME>` |
| 发布账号 / AppID | 发布配置 | 完全剔除 |

## 二、为什么用双层机制

原因是**只做一层必漏**。

### 第一层：结构化映射

按字段名处理 JSON：

```python
PERSON_ARRAYS = ("total", "legal", "employees", "rows", "detail", "list")
ORG_KEYS = ("事业部", "部门")

for row in data["total"]:
    row["姓名"] = fake_name(row["姓名"])     # 姓名映射
    row["工号"] = fake_gh(row["工号"])       # 重新编号
    row["事业部"] = DEPTS.get(row["事业部"]) # 组织映射
```

这一层能精确处理语义明确的字段，但它只认「知道名字的键」。

### 第二层：全文本全局替换

先从全部真实数据里**抽出姓名全集**，再对所有文本（含 HTML、注释、内嵌 JSON、模板字符串）做替换：

```python
def collect_real_names():
    # 递归遍历所有 JSON，收集长度 2~4 的姓名候选
    ...

# 长姓名优先，避免「张三」先被替换导致「张三丰」只剩「<假名>丰」
NAME_PAIRS = sorted(names, key=len, reverse=True)
```

这一层是兜底，覆盖第一层够不到的地方——比如**字典的键本身是人名**（`{"张三": {...}}`）、
图表配置里的图例文本、JS 拼接的 HTML 字符串。

### 关键约束：候选词过滤

全文本替换的危险在于**误伤**。最初把「姓名候选」定得太宽（只要 2~4 字、出自 `name` 键），
结果把业务词当人名替换了：

- 「网销模式」「会计模式」→ 被替换成虚构人名，Tab 标签全错
- 「开场介绍」「需求挖掘」「异议处理」「加微埋点」→ 质检维度名变成人名，结论区失去意义

**修正**：加业务词黑名单（模式 / 事业部 / 维度名 / 岗位名…），并只信任明确的「人」字段
（`姓名` / `person` / `agent` / `employee`），不再用泛化的 `name`。

## 三、数值处理

数值采取两种策略，按场景区分：

| 场景 | 处理 | 原因 |
|---|---|---|
| 页面内嵌文本中的数字 | 同比例扰动（×0.82 后取整） | 破坏反推可能性，同时保留量级 |
| 结构化 JSON 的百分比 / 比率 | 原样保留 | 比率不指向具体个人，且扰动后指标间的勾稽关系会断 |
| 金额 / 业绩 | 取整抹平 | 降低通过金额反查订单的可能 |

**重要教训**：数值扰动**只能在纯文本上做，绝不能对整个 HTML 做**。
HTML 里有 `&#28304;` 这类字符实体，正则匹配数字会把实体编码改掉，
渲染出来全是乱码——整页变天书。这个 bug 真实发生过，排查花了不少时间。

## 四、校验

脱敏后必须跑校验，而不是靠肉眼。

```python
REAL = ["<真实姓名清单>", "<公司标识>", "<城市名>"]
PAT  = re.compile(r"<磁盘盘符>:[/\\]{1,2}Users|<云厂商密钥前缀>[0-9A-Za-z]{10,}|"
                  r"key=[0-9a-fA-F]{20,}|wo[A-Za-z0-9]{12,}|<内网域名片段>")

for 每个文件 in 遍历仓库:
    if any(w in content for w in REAL) or PAT.search(content):
        报告问题
```

校验覆盖：真实姓名、公司标识、城市名、内网域名、对象存储桶、密钥、Webhook Key、
企业微信 userid、本机路径、音频地址字段名。

**当前结果：0 残留。**

## 五、遗留说明

以下几项刻意保留，原因如下：

| 项 | 为什么保留 |
|---|---|
| 页面底部的生成时间戳 | 不含个人身份信息，且能体现「数据是自动生成的」 |
| 部门数量、人员总数 | 属于结构性信息，脱敏后仍需支撑页面逻辑（如「覆盖 6 个部门」） |
| 评分维度名称 | 通用销售方法论术语，非商业机密 |
| 「演示环境」提示条 | 主动告知访客数据虚构，属必要声明 |

## 六、可复现

脱敏脚本随仓库提供（`tools/`），处理顺序：

```
1. 结构化脱敏     → 生成 demo/
2. 补充脱敏       → 健康度 / 通话质检 / 上下文 JSON
3. 资源修补       → 复制 ECharts、绝对路径改相对
4. 校验           → 扫描残留，非 0 则中断
```

真实姓名清单与映射表**不入库**（`.gitignore` 排除），仅保留方法论与脚本骨架。
